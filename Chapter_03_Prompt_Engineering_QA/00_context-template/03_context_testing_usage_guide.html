Testing Context

Records how your team tests: test types, techniques, priority meaning, tools, data rules and output formats.

Blank file: 03_context_testing.md · Filled example: 00_context-vwo/03_context_testing.md

1. Why this file matters

Templates such as 02 Test Case Design, 08 Bug Triaging and 13 Status Report use your priority scheme and tools from here, so outputs match your team's conventions.

When to fill it

Once per project or team. Update when tools or priorities change.

Golden rule

Only write what a source document says. Anything else is [Requires clarification].

2. Where to find the information

  • Team test strategy / QA handbook
  • Your test management and defect tools
  • Automation framework README

4. Step by step

  1. Copy the folder 00_context-template/ to 00_context-<project>/ (do this once per project).
  2. Open 03_context_testing.md in the copy and replace each [PLACEHOLDER] using the sources above.
  3. Delete lines that do not apply; keep [Requires clarification] for anything unknown.
  4. Compare with the filled example in 00_context-vwo/ if you are unsure of the level of detail.
  5. Save. The file is now reusable in every Daily QA template.

5. Common mistakes

MistakeDo this instead
Leaving every test type in, even irrelevant onesDelete what does not apply, or the model will generate tests for it.
Priority labels without definitionsDefine each level in one line so triage stays consistent.

6. Check before you use it

  • No [PLACEHOLDER] left unfilled (filled or marked [Requires clarification]).
  • Every fact can be traced to a source document.
  • No real credentials, tokens or personal data.
