Constraints and Guardrails

The anti-hallucination and safety rules that every prompt must follow, plus your project-specific rules.

Blank file: 04_context_constraints.md · Filled example: 00_context-vwo/04_context_constraints.md

1. Why this file matters

These rules make the model write 'Requires clarification' instead of inventing values, and stop it from producing real credentials or 'final' sign-offs.

When to fill it

Rarely. Keep the Hard Rules as they are; only add project-specific rules.

Golden rule

Only write what a source document says. Anything else is [Requires clarification].

2. Where to find the information

  • Chapter_02_Prompt_Engineering/anti-hallucination-rules.md
  • Your organisation's security and data policies

4. Step by step

  1. Copy the folder 00_context-template/ to 00_context-<project>/ (do this once per project).
  2. Open 04_context_constraints.md in the copy and replace each [PLACEHOLDER] using the sources above.
  3. Delete lines that do not apply; keep [Requires clarification] for anything unknown.
  4. Compare with the filled example in 00_context-vwo/ if you are unsure of the level of detail.
  5. Save. The file is now reusable in every Daily QA template.

5. Common mistakes

MistakeDo this instead
Removing rules to get 'more complete' outputMore complete but invented output is worse. Keep the rules and answer the open questions instead.
Pasting this block at the top instead of the endPut it last, so it is the final instruction the model reads.

6. Check before you use it

  • No [PLACEHOLDER] left unfilled (filled or marked [Requires clarification]).
  • Every fact can be traced to a source document.
  • No real credentials, tokens or personal data.
