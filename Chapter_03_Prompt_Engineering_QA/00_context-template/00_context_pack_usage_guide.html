Context Pack

Four short files that give every prompt the same project background, so you stop re-describing the product and the model stops guessing.

1. What is in the pack

#FilePurposeWhen to fill
01Project ContextDescribes the application as a whole, so every prompt knows what product, users and environments it is dealing with.Once per project. Update it when environments, tech stack or objectives change.
02Feature ContextCaptures the requirements of the one feature you are testing right now, with stable IDs.Once per feature or story. Make a copy per feature if you test several in parallel.
03Testing ContextRecords how your team tests: test types, techniques, priority meaning, tools, data rules and output formats.Once per project or team. Update when tools or priorities change.
04Constraints and GuardrailsThe anti-hallucination and safety rules that every prompt must follow, plus your project-specific rules.Rarely. Keep the Hard Rules as they are; only add project-specific rules.

Blank pack: this folder. Filled example: ../00_context-vwo/.

2. Set it up for a new project (once)

  1. Copy 00_context-template/ to 00_context-<project>/, e.g. 00_context-shop/.
  2. Fill the files in order 01 → 04, using each file's guide.
  3. Mark anything you do not know as [Requires clarification]. Do not guess.
  4. For a new feature later, only update 02_context_feature.md.

3. Use it with a prompt (every time)

  1. Paste 01, 02 and 03 first.
  2. Paste the prompt from a Daily QA template or ../Reusable_Templates/, with its placeholders filled.
  3. Paste 04 Constraints last, so the guardrails are the final instruction.
  4. Review the answer: anything marked Requires clarification becomes a question for the team, not a guess.

Paste order:

[contents of 01_context_project.md]
[contents of 02_context_feature.md]
[contents of 03_context_testing.md]

---- prompt from Daily_QA_Templates/02_Test_Case_Design_CLEAR.md ----
## C: Context
...
## R: Review
...

[contents of 04_context_constraints.md]

In Claude Code you can reference files instead of pasting, for example: @Chapter_03_Prompt_Engineering_QA/00_context-shop/01_context_project.md.

5. Keep it healthy

  • Update the pack when environments, tools or requirements change, before running prompts.
  • Never store credentials, tokens or personal data in the pack.
  • Keep requirement IDs stable so RTM and coverage reports stay comparable.
