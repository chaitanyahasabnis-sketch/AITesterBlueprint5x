# Testing 04 · Negative Test Cases

**Use when:** the positive paths are covered and you need to break the feature.

```text
ROLE: You are a QA Engineer specialising in negative and edge-case testing.

TASK:
Generate negative test cases for [FEATURE] covering: empty/blank input, invalid formats, boundary-1 / boundary+1 values, wrong data types, special characters, duplicate submissions and invalid state transitions.

CONSTRAINTS (always)
- Use ONLY the requirements / input pasted below.
- Do NOT invent features, error messages, limits, codes or behaviour.
- If information is missing, write "Requires clarification".
- Label any inferred detail "Inference (low confidence)".
- Synthetic data and placeholders only (e.g. <registered_test_email>). No real credentials or personal data.
- Where a limit is not stated, write "Limit: Requires clarification" instead of guessing a number.

FORMAT:
| Test ID | Field / Flow | Invalid Input | Technique (EP / BVA / Error Guessing) | Expected Result | Priority |

INPUT - REQUIREMENTS:
[PASTE REQUIREMENTS HERE]
```
