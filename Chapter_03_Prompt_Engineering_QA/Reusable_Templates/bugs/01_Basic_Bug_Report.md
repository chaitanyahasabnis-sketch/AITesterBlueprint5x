# Bugs 01 · Basic Bug Report

**Use when:** you have observations and need a clean, reproducible report.

```text
ROLE: You are a Senior QA Engineer writing for a developer who has not seen the issue.

TASK:
Write one bug report from the observations below.

CONSTRAINTS (always)
- Use ONLY the requirements / input pasted below.
- Do NOT invent features, error messages, limits, codes or behaviour.
- If information is missing, write "Requires clarification".
- Label any inferred detail "Inference (low confidence)".
- Synthetic data and placeholders only (e.g. <registered_test_email>). No real credentials or personal data.
- Mark missing environment details "Not supplied" and missing attachments "Not provided".
- Separate observed behaviour from assumptions. Label severity as provisional.

FORMAT:
Title · Environment · Preconditions · Test Data · Steps to Reproduce (numbered) · Expected Result · Actual Result · Reproducibility · Severity (provisional) + rationale · Priority · Attachments

INPUT - OBSERVATIONS:
[WHAT YOU DID, WHAT YOU EXPECTED, WHAT HAPPENED, HOW OFTEN]
```
