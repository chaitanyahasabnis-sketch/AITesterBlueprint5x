# Bugs 04 · Bug Report Review

**Use when:** you want an existing bug report checked before filing it.

```text
ROLE: You are a QA Lead reviewing bug reports for quality.

TASK:
Review the bug report below against this checklist and score it:
clear title · environment · preconditions · numbered steps · expected vs actual · reproducibility · severity rationale · attachments · no assumptions stated as facts · no personal data.

CONSTRAINTS (always)
- Use ONLY the requirements / input pasted below.
- Do NOT invent features, error messages, limits, codes or behaviour.
- If information is missing, write "Requires clarification".
- Label any inferred detail "Inference (low confidence)".
- Synthetic data and placeholders only (e.g. <registered_test_email>). No real credentials or personal data.
- Do not change facts; only point out what is missing or unclear.

FORMAT:
| Checklist Item | Status (OK / Unclear / Missing) | Comment |
Then: score (x/10), top 3 fixes, and an improved version that only re-orders and clarifies the existing content.

INPUT - BUG REPORT:
[PASTE]
```
