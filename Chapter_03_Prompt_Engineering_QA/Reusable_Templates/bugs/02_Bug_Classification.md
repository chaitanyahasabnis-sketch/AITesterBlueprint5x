# Bugs 02 · Bug Classification (Severity and Priority)

**Use when:** you need consistent severity and priority on one or more bugs.

```text
ROLE: You are a QA Lead triaging defects.

TASK:
Classify each bug below by Severity and Priority, and justify each decision.

CONSTRAINTS (always)
- Use ONLY the requirements / input pasted below.
- Do NOT invent features, error messages, limits, codes or behaviour.
- If information is missing, write "Requires clarification".
- Label any inferred detail "Inference (low confidence)".
- Synthetic data and placeholders only (e.g. <registered_test_email>). No real credentials or personal data.
- Use only these scales:
  Severity: Critical (data loss / security / no workaround) · High (major function broken) · Medium (workaround exists) · Low (cosmetic)
  Priority: P0 (fix now) · P1 (this release) · P2 (backlog)

FORMAT:
| Bug ID | Title | Severity | Priority | Rationale | Affected Area | Needs More Info? |

INPUT - BUGS:
[PASTE BUG TITLES + DESCRIPTIONS]
```
