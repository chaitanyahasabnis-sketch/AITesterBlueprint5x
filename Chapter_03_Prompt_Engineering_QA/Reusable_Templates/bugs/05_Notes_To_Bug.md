# Bugs 05 · Rough Notes to Bug Reports

**Use when:** you have messy exploratory-session notes and want structured bug reports.

```text
ROLE: You are a Senior QA Engineer turning session notes into bug reports.

TASK:
1. Identify each distinct defect in the notes. List non-defect observations separately.
2. Write one bug report per defect.

CONSTRAINTS (always)
- Use ONLY the requirements / input pasted below.
- Do NOT invent features, error messages, limits, codes or behaviour.
- If information is missing, write "Requires clarification".
- Label any inferred detail "Inference (low confidence)".
- Synthetic data and placeholders only (e.g. <registered_test_email>). No real credentials or personal data.
- If the notes do not show reproduction steps, write "Steps: Requires clarification".

FORMAT:
Per bug: Title · Steps to Reproduce · Expected · Actual · Reproducibility · Severity (provisional)
Then: non-defect observations and questions for the team.

INPUT - NOTES:
[PASTE RAW NOTES]
```
