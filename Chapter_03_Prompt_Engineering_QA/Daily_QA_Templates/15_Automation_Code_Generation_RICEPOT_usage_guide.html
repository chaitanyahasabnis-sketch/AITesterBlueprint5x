Automation Code Generation

RICE-POTskill: automation-code-generator

Generate automation code for supplied test cases that follows the existing framework's conventions.

Template file: 15_Automation_Code_Generation_RICEPOT.md

1. When to use it

Use when

  • Test cases are approved and selected for automation
  • Adding tests to the Playwright or Selenium framework

Skip when

  • Locators or page structure are unknown and cannot be supplied

2. How the RICE-POT framework is used here

R
Role — The expert persona the model writes as.
In this template: You are a Senior SDET working in [Playwright + TypeScript / Selenium + Java + TestNG].
I
Instructions — What to produce and the rules for producing it.
In this template: Automate the supplied test cases following the existing framework: page objects, fixtures, test data kept separate, no hard waits, web-first assertions, secrets from environment variables, one test per TC ID with the ID in the title.
C

In this template: [PASTE FOLDER TREE / FRAMEWORK GUIDE]
E
Example — A sample of the expected output to imitate.
In this template: [PASTE ONE EXISTING TEST FROM YOUR FRAMEWORK]
P
Parameters — Hard output constraints: counts, limits, labels for missing data.
In this template: - Language: [TS / Java].
O

In this template: 1. One code block per file, with its path as a heading
T

3. Gather your inputs first

  • Test cases to automate
  • Framework structure / conventions
  • Locators or HTML snippets
  • Target language and test runner

For project background, fill the blank pack in ../00_context-template/ and paste it above the prompt. ../00_context-vwo/ is a filled example.

4. Run it step by step

  1. Open 15_Automation_Code_Generation_RICEPOT.md and copy the whole Prompt block.
  2. Replace every [PLACEHOLDER] with your inputs. Leave a placeholder as Not supplied rather than guessing.
  3. Keep the GUARDRAILS block at the end. It stops the model inventing facts.
  4. Paste into Claude (or your agent) and ask for the output in the format you need (Markdown, DOCX, XLSX).
  5. Check the result against the review checklist in step 6.
  6. Save the output in ../output/ and add a row to ../MyNotes.md.

The prompt you will paste:

## R: Role
You are a Senior SDET working in [Playwright + TypeScript / Selenium + Java + TestNG].

## I: Instructions
Automate the supplied test cases following the existing framework: page objects, fixtures, test data kept separate, no hard waits, web-first assertions, secrets from environment variables, one test per TC ID with the ID in the title.
If a locator is not supplied, leave a clear TODO; do not guess.

## C: Context
Framework structure / conventions:
[PASTE FOLDER TREE / FRAMEWORK GUIDE]
Test cases:
[PASTE]
Locators / HTML:
[PASTE]

## E: Example
[PASTE ONE EXISTING TEST FROM YOUR FRAMEWORK]
The generated tests must copy its structure: imports, fixtures / page objects, naming, assertion style.

## P: Parameters
- Language: [TS / Java].
- Files to create or modify: [LIST].
- At most [N] files.
- Credentials only via env vars.

## O: Output
1. One code block per file, with its path as a heading
2. The command to run the tests
3. Assumptions and TODOs

## T: Tone
Production-quality code; comments only where the intent is not obvious.

GUARDRAILS (always apply)
- Use ONLY the information pasted into this prompt.
- Do NOT invent requirements, IDs, error messages, numbers, dates or behaviour.
- Missing information -> write "Requires clarification" or "Not supplied".
- Inferred information -> label it "Inference (low confidence)".
- Synthetic data and placeholders only (e.g. <registered_test_email>). No real credentials or personal data.
- Finish with a short Self-Check: list anything you could not trace to the input.

5. Worked example (VWO login)

Input (excerpt): TC-006 Submit with empty password (expected: not logged in).

Good output looks like:

test('TC-006 empty password does not log in', async ({ loginPage }) => {
  await loginPage.fill(env.email, '');
  await loginPage.submit();
  await expect(loginPage.page).not.toHaveURL(/dashboard/);
  // TODO: assert validation text once confirmed (Requires clarification)
});

6. Review before you trust it

  • Follows existing page objects and fixtures
  • No hard-coded credentials
  • No guessed locators
  • Run command provided and works
